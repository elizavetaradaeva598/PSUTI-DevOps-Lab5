# Управление квотами билетов на события (Вариант 13)

Это веб-приложение для просмотра мероприятий и управления квотами билетов на них. В интерфейсе для каждого события видно:
- **вместимость площадки** (сколько человек максимум помещается на площадке);
- **квоту билетов** (сколько билетов разрешено продать/распределить на это событие);
- **число проданных билетов**;
- **оставшиеся места** (сколько билетов ещё свободно).

Приложение состоит из трёх компонентов, запущенных в Docker-контейнерах:
1. **База данных (`db`)** - PostgreSQL с расширением PostGIS, где хранятся события, площадки, бронирования и данные о квотах.
2. **Бэкенд (`backend`)** - готовый сервер API (`kazan-events`), который проверяет правила (например, нельзя поставить квоту меньше проданных билетов или больше вместимости площадки) и работает с базой данных.
3. **Фронтенд и веб-сервер (`nginx`)** - веб-страница с интерфейсом управления квотами и Nginx, который отдаёт эту страницу в браузер и пересылает запросы к API на бэкенд.

---

## Что нужно перед началом

Чтобы запустить проект у себя на компьютере или виртуальном сервере, понадобятся:
1. **Установленный Docker и Docker Compose** (в современных версиях Docker команда пишется через пробел: `docker compose`).
2. **Доступ к интернету** при первом запуске - Docker сам скачает нужные образы контейнеров (`postgis/postgis`, `ghcr.io/nelkor/kazan-events`, `nginx`).
3. **Терминал** (например, PowerShell на Windows или обычный терминал / SSH-подключение на Linux/Ubuntu).

Проверить, установлен ли Docker и работает ли он, можно командой:

```bash
docker compose version
```

## Как запустить приложение

1. **Скачайте проект и перейдите в его папку.** Если репозиторий ещё не скачан, склонируйте его и зайдите внутрь:

```bash
git clone [https://github.com/elizavetaradaeva598/PSUTI-DevOps-Lab5.git](https://github.com/elizavetaradaeva598/PSUTI-DevOps-Lab5.git)
cd PSUTI-DevOps-Lab5
```

*(Если файлы уже лежат у вас на компьютере, просто откройте терминал в папке проекта, где находится `compose.yml`.)*

2. **Запустите сервисы в фоновом режиме:**

```bash
docker compose up -d
```

Docker Compose создаст общую сеть и том для базы данных, скачает нужные образы и запустит `db`, `backend` и `nginx`. При первом запуске на подготовку базы и загрузку тестовых данных может уйти около минуты.

3. **Проверьте статус контейнеров:**

```bash
docker compose ps
```

Убедитесь, что все три сервиса в состоянии `Up`, а у `db` и `backend` статус проверки здоровья — `healthy`. Если что-то пошло не так, логи можно посмотреть командой `docker compose logs`.

## Как открыть и пользоваться приложением

- **Адрес в браузере:** откройте `http://localhost:8080` (или `http://<IP-адрес_сервера>:8080`, если проект запущен на удалённой машине или виртуальном сервере). Интерактивная документация API (Swagger) доступна по адресу `http://localhost:8080/docs`.
- **Сводка и карточки событий:** сверху показаны общие цифры по загруженным событиям, а ниже — карточки с четырьмя показателями: **Вместимость** площадки, **Квота**, **Продано** и **Осталось**.
- **Поиск, фильтр и сортировка:** список можно отфильтровать по слову в названии или описании, выбрать нужный статус события или поменять порядок сортировки, а кнопка **«Обновить»** заново загружает данные с сервера.
- **Изменение квоты билетов:** введите в карточке события новое целое положительное число (или воспользуйтесь кнопками быстрой подстановки минимума по продажам / максимума площадки) и нажмите **«Сохранить»**. Сервер не даст поставить квоту меньше уже проданных билетов или больше вместимости площадки — если ввести неподходящее значение, под формой появится пояснение.

## Как остановить приложение

- **Остановить контейнеры, сохранив данные базы:**

```bash
docker compose down
```

Данные останутся в томе `pg_data`, поэтому при следующем `docker compose up -d` все изменения квот сохранятся.

- **Остановить контейнеры и полностью очистить базу данных** (чтобы вернуть исходные тестовые данные с нуля):

```bash
docker compose down -v
```
